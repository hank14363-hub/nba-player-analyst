# NBA Player Analyst问题检查与修复 · v0.8.4

## 已确认的问题

1. **主流程默认漏掉比较。** SKILL在线示例不含--comparisons，CLI默认关闭；勒布朗案例已有四张582人联盟表，却没运行比较。离线核验可得到270名轮换和12名组织核心。修复：新run_analysis默认尝试已有表，支持--no-comparisons；失败给具体原因，不额外取数。
2. **未启用被呈现成证据缺失。** 旧模块提示容易让读者以为结论丢失。修复：未启用单独说明；缺失或核验失败仍保留原因。
3. **写作完成度缺少审查。** 校验只要求解读非空，勒布朗五张卡重复通用application与boundary仍通过。修复：editorial_audit报告已知套话、重复说明、空主题、比较可算未启用、比较已算未写；新成果可用--strict-editorial拦截。它只能发现明显遗漏，不能评价篮球判断真伪。
4. **BR五轴完整模块未适配。** 旧研究册继续访问非受助攻总命中、PIE、team_count与旧敏感性字段；BR身份字符串还导致本球员不高亮。修复：按来源选择五轴字段、BR标签和正确目标，兼容已保存BR上下文，无PIE代理。新增实际模块渲染测试。

## 使用

新分析运行run_analysis.py时无需额外--comparisons；完整联盟样本通过时会输出比较，失败则保留原因。仅研究狭窄问题且明确不需比较时，可加--no-comparisons。

新研究册完成后：

```text
python <SKILL_DIR>/scripts/validate_book.py --run-dir <研究目录> --strict-editorial
```

editorial_audit不是能力评分；no_flags不代表全部结论正确。旧request仍按原逻辑复算，不会自动修改已有指标。要更新勒布朗研究册，需要另建输出目录、补算比较、补写并登记同角色解读，再重建研究册。

## 仍需改进

EPM访问与历史样本不足仍是数据限制；不能靠校验器补齐。自动语义审查尚未实现，仍需人工检查推断与证据匹配。当前套话识别针对已确认失败和明显重复，并非完整语言质量模型；以后用真实阅读反馈扩充，避免为通过检查填充内容。
